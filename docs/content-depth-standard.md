# 知识深度与覆盖标准

日期：2026-11-07。状态：根据用户“偏浅、不够全面”的反馈修订。

## 1. 深度属于知识库，节奏属于学习轮次

知识库要保存足够深入的解释、推导、实现、比较、适用条件和联系。每轮只按个人当前能力展开其中一部分。初学者入口容易，不代表知识档案可以停在摘要。

原来的8张短卡保留为入口，新增对应深入档案。短卡不能被计作该算法已经全面建成。

## 2. 每个核心实体的八个检查面

| 检查面 | 必须能回答的问题 | 不足的例子 |
| --- | --- | --- |
| 问题与直觉 | 解决什么问题？为什么需要？例子与反例是什么？ | 只有一句定义或比喻 |
| 定义与符号 | 对象、输入、输出、公式、形状、约定和适用条件是什么？ | 公式没有符号说明 |
| 推导与机制 | 怎样从前提走到更新或输出？每步为何成立？ | 只给最终公式 |
| 实现与实验 | 怎样算、怎样检查、怎样复现？计算代价与数值问题是什么？ | 只有伪代码，没有检查样本 |
| 对比与变体 | 与近邻方法有什么相同、不同、替代和条件等价？ | 罗列名字，不解释差别 |
| 边界与排错 | 哪些结论不成立？失败怎样定位？ | 把一次实验当普遍定理 |
| 图谱与迁移 | 与前置、后续和跨领域概念怎样联系？ | 每篇文章是孤岛 |
| 任务与评价 | 怎样检验解释、推导、实现与迁移？如何按缺口回补？ | 只问“是什么”或给唯一背诵答案 |

不同实体可有不适用项，但必须写原因。术语节点不必强行套算法复杂度；算法节点不能省略机制或边界。

## 3. 认识、理解、实现和研究分开

- 入门层：能说出问题，识别现象，完成一个小实验。
- 机制层：解释关键关系，推导代表性步骤。
- 实现层：从头算或写出核心计算，检查维度、数值与复杂度。
- 迁移层：比较方法、诊断失败，在新情境选择并解释方案。
- 研究层：核查原论文假设与证据、变体和未解决问题。目录或延伸阅读不能冒充研究层内容已完成。

这是每个实体的能力目标，不要求按固定层级刷题。状态由相应证据决定。

## 4. 全面性分三张账

1. 领域覆盖：还有哪些算法、机制和变体未登记？
2. 实体成熟度：登记条目是否有来源、深入解释、可复现样本和完整关系？
3. 教学成熟度：解释与关卡是否已审校、试玩和延后验证？

不以节点数、文档长度、标题齐全或校验通过代替这些判断。覆盖报告应同时公开未完成项。

## 5. 本批交付边界

为既有8张入口卡增加分层深入档案，并加入可运行的标准库数值实验。内容仍为待独立审校草稿，新增章节不自动升级实体为已审核。

先补核心知识的纵深，再持续扩大全局算法来源与分支。Transformer的现代训练、推理、位置机制与高效实现等后续实体分别登记缺口，不能用“Transformer已介绍”代替这些内容。
