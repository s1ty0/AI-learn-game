# 首版数据模型

日期：2026-11-07。状态：完整逻辑设计；首个子集已建立Alembic迁移并在PostgreSQL运行，未全部实现。

当前已建立11张表：content_releases、entity_revisions、relation_revisions、learner_graphs、graph_snapshots、graph_operations、attempts、adventure_sessions、intake_sessions、guidance_sessions、verification_sessions。实际定义见apps/api/app/models.py与migrations/versions/0001_initial.py、0002_adventure.py、0003_intake.py、0004_guidance.py、0005_verification.py。其余表仍为后续设计。

adventure_sessions单独保存小岛探索阶段、修订、内容版本及带操作键/条件/提示/规则版本的追加事件。探索发现使用现有公共实体ID，不创建重复概念；探索奖励不等同掌握证据，也不覆写旧地图。

回声小岛使用local-demo，分光台使用local-demo:prism，分开记录阶段，不增加或删除原图。分光台请求携带三个偏好分数、权重和输出，由服务端独立Softmax复算；其内容草稿在内容版本清单中另存prism_lesson并参与版本哈希。该固定关卡实现尚未扩展为通用关卡实例/任务发布模型。

当前已补信息之海局部章节：local-demo:query、local-demo:heads、local-demo:beacon三个独立探索记录，仍复用原表。内容清单保存chapter配置与chapter_lesson，参加版本哈希。章节主线完成与全探索完成由各点阶段重算；支线不阻塞主线终点。阶段事件保存查询、未来值、光闸、观测、关系选择或机制链及提示/规则版本；不会写熟练度或掌握投影。

原型将限定专题正文与练习源副本放在内容清单JSONB中；作答评价暂存于attempts的JSONB，记录内容与数值规则版本，解释统一待复核。尚无独立评价/掌握投影表。关系端点由导入数据检查保证可解析，当前数据库尚未建立端点复合外键；完整约束需在后续迁移补齐。

## 1. 内容源与运行数据分工

Markdown与JSON仍是可审阅的内容源。内容ID保持现有编号，导入后以版本化记录供应用读取。用户回答、解释、图谱修订和学习证据只写运行数据库，不混回公共知识文件。

PostgreSQL中的结构字段用表、外键、索引和唯一约束表达；JSONB只保存适合结构变化的局部负载，避免将全部世界图变成无法追溯的大文档。

## 2. 公共内容

| 表 | 核心身份与约束 | 内容 |
| --- | --- | --- |
| `content_releases` | 内容版本ID、清单哈希、发布状态 | 导入/审校/发布记录与源文件清单 |
| `entity_revisions` | 实体稳定ID + 内容版本唯一 | 名称、别名、类型、领域和正文引用 |
| `relation_revisions` | 关系稳定ID + 内容版本唯一 | 起点、终点、命题、条件、关系类型与审核状态 |
| `source_revisions` | 来源稳定ID + 内容版本唯一 | URL、版本、查看范围、使用条件与核查日期 |
| `task_revisions` | 任务ID + 内容版本唯一 | 目标、题族、形式、提示、先修条件与可公开内容 |
| `rubric_revisions` | 量规ID + 量规版本唯一 | 核心要点、严重错误、可接受变式与补学路由 |

关系端点必须解析到该内容版本中的实体。硬性先修与一般关系分别校验，普通关系可以回环；先修组需要保存AND/OR含义，不把所有入边当作必修。

量规的运行读取权限与公开正文不同；不把整条任务记录无筛选返回客户端。

## 3. 学习者与证据

| 表 | 核心字段 | 必须保留的区别 |
| --- | --- | --- |
| `learner_profiles` | 学习者ID、目标、偏好、初始诊断状态 | 自报熟练度与验证证据不同 |
| `attempts` | 学习者、任务版本、题族、回答、提示、操作键、时间 | 独立回答与支持下完成不同 |
| `evaluations` | 作答ID、量规版本、评价来源、结果、依据、模型元数据 | 原始评价与纠正记录不同 |
| `mastery_evidence` | 对应实体/关系、理解深度、作答与评价引用 | 认识节点与理解关系不同 |
| `mastery_projections` | 学习者 + 目标/深度、当前状态、证据集合、规则版本 | 当前投影可以重算，历史证据不能被覆盖 |
| `recommendations` | 目标、所选任务、依据证据、规则版本、候选缺口 | 选题决策可解释、可复查 |

状态沿用未知、学习中、支持下完成、独立验证、待复核。阶段完成与节点熟练分别记录；当前记录只覆盖其内容版本和理解深度，不推断相邻全部知识。

评价纠正使用追加记录并说明原因，不静默覆盖原结果。到期复验失败可以改变当前投影，但不删除历史通过证据。

## 4. 个人图谱版本

| 表 | 核心字段 | 约束 |
| --- | --- | --- |
| `learner_graphs` | 图ID、拥有者、当前revision | 只能操作本人或明确授权的图 |
| `graph_operations` | 图ID、操作键、基于revision、类型、前后负载 | 图ID+操作键唯一，重复提交不重复创建版本 |
| `graph_snapshots` | 图ID、revision、内容版本、节点/关系/布局负载 | 图ID+revision唯一，已提交快照不可覆盖 |
| `stage_submissions` | 阶段、快照ID、评价引用、内容/任务版本 | 不随玩家后续编辑而改变 |

图快照保存个人解释、自建节点、映射状态、连线命题及布局。权威掌握证据仍引用独立证据表，不因拖动或连线直接变为已掌握。

恢复旧图产生新快照，并记录`restored_from`，复制的快照仍引用原内容版本。若要映射到新课程，作为一次显式迁移另记，保留旧成果。

## 5. 并发与一致性

同一事务内锁定或条件更新图头revision，写操作记录、新快照和图头。相同操作键重试先返回已记录结果；不同操作基于过期revision时返回冲突，避免覆盖。

作答提交与评价保存分开：外部模型评价可能耗时，作答先进入待评价状态。模型回调或重试使用幂等键，不重复发放通过证据；主服务中断后仍可从已保存作答重试。

当前不建设通用事件溯源平台。追加证据、可重算投影和图快照满足首版审计与恢复要求，避免把所有业务变化都强行实现成复杂事件系统。

## 6. 查询与索引重点

- 关系按内容版本及起点/终点索引；局部遍历限制深度和返回数量。
- 作答与证据按学习者、目标、题族和时间查询，重复题族不算多个独立证据。
- 图快照按图ID与revision查询；版本列表只取元数据，按需加载快照。
- 名称、英文、别名优先做确定匹配；中文正文检索需用实际查询集验证效果。
- 模型调用记录请求ID、来源版本、提示版本、延迟与可获得的计费信息；凭据不写入业务记录。

## 7. 首轮迁移与验收

1. 用Alembic建立内容与个人学习表，正式Schema以迁移文件为准。
2. 导入当前目录时保留草稿状态；不能因数据字段齐全就发布。
3. 验证一份图在两标签页提交时的冲突，以及断网重试幂等行为。
4. 验证旧快照、阶段评价和内容版本可以同时回看。
5. 验证当前图恢复为新revision，原历史不被删除。

首轮已验证图保存/刷新、不可覆盖的历史、恢复为新修订、操作键幂等、过期及真正并发提交冲突、作答留痕与伪造数值拒绝。完整阶段评价、旧课程界面、身份隔离、断网重试全链路及备份恢复仍待验收，不能把首轮数据库检查等同于完整数据模型完成。

2026-11-08多章扩展复用`adventure_sessions`，为12个新节点只补缺失会话。每步追加输入、观察值、原因、提示使用、操作键、请求摘要、时间和规则版本；章节配置及三份机制正文进入内容版本。未增加数据表或覆盖旧个人图快照。发现可在“我的发现”回看，但探索继续标记`unverified`；题库、熟练度与正式迁移证据尚未建立。
