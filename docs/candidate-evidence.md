# 掌握候选证据与延后复验

日期：2026-11-09。状态：四类目标的工程首版；规则阈值、真实人员独立性和学习效果尚待校准，不是正式掌握认证。

## 1. 玩家在哪里看

“更多→把关系讲通”新增候选证据面板。提交初次新情境后，逐条显示已记录与待补齐条件；缺少依据时说明缺口，不把未知写成不会。默认不展开全图、熟练度百分比或解锁奖励。

初次条件齐备后，按服务器时间等待自初次提交起满72小时，再开放结构不同的复验情境。等待不影响继续游戏、补学、星图整理或普通验证。72小时是本版开发假设，不宣称是最佳记忆间隔，也不保证期间没有复习。

## 2. 候选准入检查什么

初次作答与复验分别检查同样六项：

1. 本题判断符合确定规则；未知或错误预测不能用复核勾选抵消。
2. 作答未标记使用帮助；复核者的无帮助声明不能抹去学习者已提交的帮助标记。
3. 不是同题族重做；看过参考答案再做同题不能变成新独立证据。
4. 至少两个配置身份逐项复核；同一人追加纠正不增加人数。
5. 当前逐项全满足且没有分歧；部分、缺失、不确定或争议均需补充。
6. 至少一位复核者记录了实际无帮助观察依据，且当前最新观察中没有帮助声明冲突。仅有答案、自报或身份钥匙不足以确认。

第六项是对复核者观察声明的记录检查，不是系统证明了现实独立性。其他复核者仍可保留无法确认；至少两身份不保证真实人员不同或具有资质。本人复盘不计入复核人数，也不改变这些条件。

## 3. 复核者怎样记录观察

工作台新增“独立性观察记录”，默认无法确认。只有实际观察过程或可核查材料时，才选“实际观察到未使用帮助”或“实际观察到使用帮助”，并说明依据。不能只因解释写得好或学习者自报独立就勾选确认。

观察与逐项意见一起追加、绑定复核者和任务；纠正仍需说明原因，历史不覆盖。候选计算使用每个身份的最新意见与观察，旧声明继续可回看。观察声明的纠正理由和充分性仍需人工复核；不改写学习者帮助标记。旧版本复核没有观察字段时按无法确认处理，不补写独立事实。

## 4. 四类复验怎样变化

| 初次目标 | 复验关系 | 核心变化 |
| --- | --- | --- |
| 因果读取 | 改变读取规则后比较两种等权平均 | 从范围外变化，转到规则本身改变；不能直接套用不变结论 |
| 权重汇聚 | 从输出反推未知输入，讨论零系数 | 从正向计算转为反推及可辨识条件 |
| 查表表示 | 同步重排词表编号和向量表 | 从按编号查行，转到映射不变和只改一方的反例 |
| 平均平方误差 | 平均指标更小是否代表逐样本更好 | 区分总体指标、单个样本与未见数据结论 |

四题源在 `apps/api/app/recheck_content.py`，与初次题分开版本化。复验开始前不返回新题答案或量规；提交后再对照和复核，原文固定。同一个来源目前只开放一次这套复验，失败或使用帮助不会靠重复同题自动获得资格；后续需要新的独立任务或明确的补证据流程。

## 5. 候选状态怎样变化

| 状态 | 玩家含义 |
| --- | --- |
| needs_evidence | 初次证据尚不齐，先看具体缺口 |
| waiting_interval | 初次条件已齐，等待满72小时 |
| ready_for_recheck | 可开始新情境复验 |
| recheck_in_progress | 复验已开始，在验证室续接 |
| recheck_needs_evidence | 复验仍缺判断、解释复核或观察依据 |
| candidate_ready | 当前记录满足本版候选条件，仍不认证永久掌握、不自动解锁 |
| needs_policy_review | 规则版本或间隔记录需明确核对，不能静默迁移 |

候选面板每次读取都按当前复核重新计算。来源后来出现分歧、帮助观察或缺项时，候选资格退回待补；复验原文和旧意见仍保留。来源纠正后按最新记录重新核对，不覆盖历史，也不因为曾经齐备就永久保持通过。

复验开始保存来源ID、当时来源复核修订、规则版本、最早时间、任务副本与星图修订。之后来源修订变化会重新检查当前条件，历史保存的修订仍可追溯。复验结束还需自己的逐项复核与观察，不能沿用初次的观察代替。

## 6. 时间、并发与恢复

GET `/api/v1/candidates` 是只读投影，返回服务器时间、规则版本、分页每次至多50个来源及条件，支持回看更早来源。POST `/api/v1/verification/actions` 新增start_recheck，要求来源ID、当前来源复核修订及验证室修订；时间和条件由服务端判定，客户端传旧时间不能提前开放。

事务先锁验证室，再锁并重新读取来源复核。来源版本过期或其他窗口先开始时返回409；重读验证记录也会刷新候选版本。新复验沿用已有解释草稿、提交、引用复盘、权限和恢复流程，不覆盖其他未完成情境。候选读取失败不冻结普通验证和返回。

使用现有JSON事件扩展，没有新表或迁移，仍为13张表。旧验证/复核操作键兼容重试，旧观察保持未知。规则变版时不把旧复验自动套进新认证条件。当前没有定时推送，需打开/刷新面板查看服务器状态。

## 7. 验证与后续

隔离数据库覆盖未知/帮助/重复题族、观察依据校验、帮助声明冲突、72小时精确边界、时间伪造、来源版本过期、完整候选链、分歧退回、并发开始、旧请求重试及四类新题。浏览器使用独立夹具验证缺口/等待/开始/提交、来源冲突同步、503重试、观察记录、手机和候选读取故障，不推进真实玩家记录。

下一批优先把这些候选/待补/待复验状态接到个人星图的对应知识与关系，提供回看和补学入口；正式掌握与跳级仍须补真人独立性、量规校准、迁移覆盖和明确先修替代证据。
