# 动态知识图谱规范草案

日期：2026-11-07。状态：概念与行为设计；不是已实现的数据结构或图数据库。

## 1. 三层结构

公共收录范围见[算法知识总图](./algorithm-atlas.md)。损失函数、梯度下降、L2 正则化、Transformer 等均需有正式身份、档案和关系；算法、架构、损失与数学基础通过实体类型区分。图谱不仅支持学习，还承担资料组织、搜索导航、持续核查和更新的职责。

| 层 | 管理内容 | 更新方式 |
| --- | --- | --- |
| 公共图谱 | 概念、命题、关系、条件、来源、深度和任务 | 内容审校后发布新版本 |
| 个人图谱 | 个人表达、自建节点、关系理解、误解与学习证据 | 根据作答、解释、实践与玩家编辑持续更新 |
| 当前局部视图 | 当前目标附近的已知点、断点、可探索连接 | 随目标和视野变化展开，不复制底层节点 |

个人图谱通过稳定 ID 关联公共图谱，不要求个人用词或布局完全一致。自建概念保留临时身份；映射到公共概念时记录确认过程，不能只凭词语相似自动合并。

## 2. 节点需要记录什么

公共节点：ID、名称、定义、适用范围、深度、例子与反例、来源、版本、审核状态、关联任务。

个人节点：公共引用或自建标记、个人解释、当前深度、学习状态、评价证据、不确定项、误解记录、创建与更新时间。

同一概念可以有直觉理解、形式解释、实现和边界分析等目标。某一深度通过不自动认证更深层次。

## 3. 关系需要记录什么

关系包含 ID、起点、终点、类型、可读命题、条件、来源、版本、验证任务与个人证据。

关系类型初步包括：组成、用于、对比、影响、例证、类比和硬性先修。不要把“有关联”当作所有连线的默认含义。

类比应标明不是事实等同；影响和因果不能混用；条件不同的命题分别保留。

硬性先修单独用于解锁，不允许循环；其他关系允许回环。AND/OR 先修组显式记录：全部满足或存在一条已验证替代路线，不能把所有入边一律视为必修。

## 4. 动态变化与历史

以下变化分别记录：

1. 内容变更：公共定义、关系或任务更新，引用旧版本的成果仍可读取。
2. 理解变更：玩家修改解释、添加或删除连接，保留修改前后内容。
3. 证据变更：任务评价或复验改变当前判断，保留原始证据及新判断理由。
4. 展示变更：折叠、展开、布局变化不改变掌握状态。

自动保存保留编辑历史；阶段提交建立不可覆盖的快照。恢复历史创建新版本，不能删除之后的记录。

历史图视图应同时显示当时解释与当时的评价状态；当前掌握判断可以另行展示，不回写旧快照。对误判的纠正追加记录，不能静默修改历史评价。

AI 建议、玩家原文和已采纳修改分别保存。编辑一条关系不能直接使它成为“独立验证”。

## 5. 怎样判断打通

为每个目标指定一份目标契约：关键节点、关键关系、需要的深度、可替代路径、综合应用任务和评分规则版本。

当次打通须满足：

- 目标必需节点及关系具备相应深度的独立证据。
- 能沿关键关系说明已知知识怎样支持目标结论。
- 能在阶段要求的新情境中应用，并说明重要条件。
- 没有尚未解决的关键矛盾。

系统对图的遍历只能检查结构是否存在；能否理解需由解释和任务证据检查。延后复验用于确认保持情况，不把一次通过表述为永久记忆。

未通过时指出具体断点，例如“能区分训练和测试，但尚不能解释为什么反复依测试调参会影响独立评估”，并关联补学任务。

## 6. 小型示例

引用课程骨架中的 C006—C009：

- C006 训练数据：用于调整模型。
- C007 独立测试数据：用于估计未见数据上的表现，保留独立性条件。
- C008 泛化：关注模型在未见数据上的表现。
- C009 过拟合：结合训练内外表现及受控条件解释现象。

玩家可能已验证 C006，却将 C007 连成“用于反复挑选最好的模型”。此时可保留 C006 的证据，标记对应关系待复核，生成评估独立性的桥接任务，而非让其重学所有基础。

这只是关系验证的设计示例，不是已经审核、发布或判分的学习样本。

## 7. P1 数据规范需落实的检查

- 节点、关系、任务和来源引用能解析到正确版本。
- 硬性先修无循环；概念关系允许合法回环。
- 每个目标有从可诊断入口出发的任务路径，不存在永久锁死的必修项。
- 关键节点和关键关系均有验证任务，且能区分不同深度。
- 未审核、自建、待映射和已验证状态能够区分。
- 公共内容更新、个人编辑、评价变更和历史恢复可分别追溯。
- 内容收录、内容审核、游戏实现与玩家掌握分别记录；某条目尚无关卡不妨碍其进入全局目录和来源维护队列。

首版已选择JSON内容源、PostgreSQL运行数据与React Flow图谱界面。公共关系、个人理解和历史快照分别存储，图数据库按真实查询瓶颈再评估。详见[技术选型](./technical-decisions.md)与[数据模型](./data-model.md)；当前仍是设计，尚未实现应用持久化。
