# 整体规划复核

更新日期：2026-11-09。依据当前仓库、已验证工程功能与用户确认的产品方向；不是用户试学结论。

## 1. 产品主线保持什么

帮助初学者通过游戏理解AI与大模型知识。公共地图持续收集和维护；玩家每次只看到当前可够到的一小块，并逐渐形成自己的知识网络。节点和关系都需要理解证据，个人图要持续留痕。

“九章通关”与“学会相关知识”分别判断。关卡数量衡量可玩范围，独立解释、迁移和延后复验才支持掌握判断。

| 方面 | 已有产物 | 剩余缺口 |

当前最影响产品目标的缺口，是“关卡发现→自己的解释和关系→下一步该学什么”尚未完整接通。继续堆章无法单独解决这个问题。

## 3. 接下来按什么顺序开发

### 第一步：个人星图，本批完成

入口保持次级。只展示已发现知识，主动接入、写解释、连接关系并保存版本。沿用同一份个人图，不产生两套互相冲突的成果。实现范围见[个人星图](./personal-star-map.md)。

### 第二步：约10任务初始画像，已实现工程首版

- 先制作少量原创任务族，按已有证据选下一任务；允许“不知道”，不把速度作为单独评分依据。
- 保存任务版本、回答、提示、评价要点、已知/待验证/未知项；不设置虚假的精确掌握概率。
- 输出少量起点建议与原因，接回当前游戏。已有玩家可以继续原进度，不强制重置和补考。
- 验证零基础、有编程基础和有数学基础三种路径；未测到的内容不能判为不会。
- 约10任务只做粗略分流。跳过关键先修还需相应独立挑战，不凭自报或一题答对大范围跳级。

### 第三步：可解释规则路线，已实现局部首版

用先修、提示依赖、独立变式、个人反馈推荐小目标。首次实现“太难”“太简单”“换个例子”，区分操作困难和知识缺口。对过易内容压缩，对具体断点补桥，不让一次失误导致整章重学。

先选择少量代表节点和关系校准规则，再扩大范围。现有“探索完成”继续保留，不回写为已掌握，也不自动撤销旧探索记录。

### 第四步：独立评价与试学，角色复核工作流已实现，真人校准待补

为代表机制准备新情境、解释要点和复验。独立题与日常提示分开；通过后记录证据及量规版本。小范围真实试学修正节奏和误解，再扩展验证范围。

### 第五步：多Agent A0—A1

先验证资料向导能否缩短搜索、引路人能否提供合适的小提示，再实现统一运行契约和确定规则回退。之后接真实提供方、陪练、验证官及绘图提案。详见[多Agent计划](./agent-system.md)。

## 4. 持续推进的工作

来源定位、内容审校、纠错、更新队列和缺口报告持续进行。后续算法继续登记；新增章节先检查操作目标、变式、关系、反例和可验证性。深入内容可以完整，单轮呈现仍控制在一个核心目标。

刷题熟练度不提前变为积分任务。其等级、题族和证据规则后续单独设计。公开服务上线还需账号隔离、备份恢复、来源使用范围和成本方案；本次不把本地原型当生产服务。

## 5. 完成怎样判断

| 里程碑 | 可检查结果 |
| --- | --- |
| 个人星图 | 发现能接入；旧文字/隐藏内容保留；草稿、冲突、历史可恢复 |
| 初始画像 | 三种基础有不同推荐起点；未知项保留；原游戏进度不被重置 |
| 规则路线 | 能说明推荐理由；过难有局部补桥，过易有压缩；未经验证不跳关键先修 |
| 关系打通 | 新情境中解释关键关系和条件，图上连通本身不能通过 |
| Agent试运行 | 有可追溯依据和失败回退，不能凭生成文本自动授予掌握或覆盖图谱 |

自动检查能证明工程规则按预期运行。是否真的“刚好够得着”、是否理解并记住，需要真实试学与复验，当前保持待验证。
