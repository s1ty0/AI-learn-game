# 邀请内测发布准备

对应PLAN的S2与计划tag `v0.1.0-invite-beta`。本机恢复、升级和账号隔离用于S1验收。S2需要可访问的线上环境、域名、运维权限与实际演练记录。

2026-11-11用户调整为开放注册。当前公网部署设置 `LEARN_OPEN_REGISTRATION=1`，不填邀请码即可创建独立账号；匿名本机档案仍关闭。以下历史邀请模式演练记录保留，新增注册验收按当前开放策略执行。

2026-11-10已通过本机生产演练。独立空数据库迁移到0007，Next.js生产构建通过临时本机HTTPS入口访问，验证匿名拒绝、无效/重复邀请拒绝、Secure Cookie、双账号图谱隔离与退出。临时证书仅用于本机演练；外网证书、监控、线上备份恢复和发布回滚仍需在目标环境验收。

## 首发拓扑

Web、API和PostgreSQL沿用现有技术栈。入口域名提供HTTPS，Web与API通过同源访问。API和数据库端口仅监听内部地址。内测初期每个服务一个实例，限制入口流量，采集进程日志并观察数据库连接数。

| 服务 | 发布配置 |
| --- | --- |
| Web | 用锁定的Node与pnpm安装，设置 `LEARN_API_ORIGIN` 指向内部API后执行 `pnpm build`，随后 `pnpm --filter @learnai/web start` |
| API | 从 `apps/api` 用锁定的Python依赖安装。配置受保护的 `DATABASE_URL`、`LEARN_WEB_ORIGIN=https://内测域名`，令 `LEARN_LOCAL_DEMO=0`；先 `python -m alembic upgrade head`，再 `python -m uvicorn app.main:app --host 127.0.0.1 --port 8000` |
| PostgreSQL | 独立内测数据库、最小访问范围、独立备份存储。只迁移经确认应进入线上环境的档案 |
| HTTPS入口 | 转发到Web，并保证原始Origin可核对。固定TLS续期、请求体和并发限制以及日志字段，账号表单、Cookie、邀请码和数据库凭据排除在日志外 |

若Web和API同机，`LEARN_API_ORIGIN`可使用`http://127.0.0.1:8000`。上述命令供同机部署验收，最终按选定环境补服务托管、域名和监控配置。

## 上线验收顺序

1. 固定待发提交，确认数据库迁移号、备份时间和回滚目标。先把备份恢复到独立数据库，验证代表性账号的登录、星图历史、作答与跨账号拒绝。
2. 启动线上服务，核对外网HTTPS、有效证书、启动日志、匿名学习接口拒绝和`/api/v1/health`。健康接口用于进程探测，同时执行需要数据库的只读业务探测。
3. 使用全新浏览器走无需邀请码注册、退出、重新登录和重复用户名拒绝流程。若另行选择邀请模式，则关闭开放注册并重新部署，再生成一次性邀请码，核对过期和重复使用拒绝。
4. 用两个账号保存不同进度与解释，验证跨设备续玩和越权拒绝。配置异常通知，模拟故障并记录探测/通知和恢复时点。
5. 演练应用回滚。先核对旧应用是否兼容当前迁移；存在新账号时保留新表，使用兼容版本或从备份另建库验证后切换。记录恢复耗时和可恢复到的时点。
6. 完成全部项目后在验收提交创建并推送带说明的tag。记录线上版本、数据库迁移、验证结果、已知问题与回滚步骤，交给用户自行体验。

公开首发与春招材料分别由后续验收触发。用户确认内测体验OK后，再整理项目八股和简历证据。
