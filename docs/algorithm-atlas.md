# AI 与大模型算法知识总图

日期：2026-11-07。状态：首批覆盖目录草案，尚未逐条检索、审校或制作关卡。

当前 `data/catalog/` 包含15个领域、160个候选实体、42条来源记录、31条待核查关系和8项维护任务。来源包含技术参考、教学组织对标及1条无法访问的域名记录，不能把来源总数当作技术证据数量。另有8张中文摘要、8份深入档案、16条术语说明与[Transformer贯穿专题](../knowledge/zh-CN/transformer/README.md)，均未通过独立教学审校。专题含图解、4篇模块文档、教学小模型及任务草案。详见[深度缺口](./depth-coverage.md)、[站点对标](./site-benchmark.md)和[覆盖报告](./catalog-coverage.md)。

## 1. 产品使命

持续收集、核查、组织和改进 AI 与大模型领域的知识，把分散的算法与资料连接成可探索、可学习、可验证的游戏地图，减少学习者反复搜索、筛选和拼接知识的时间。

损失函数、梯度下降、L2 正则化、Transformer 都是正式地图中的可寻址知识，不只作为某一课程的附带术语。覆盖对象包括算法、目标函数、架构、训练方法、推理方法、数学基础、评价方法和工程机制，按实体类型区分，避免混为一类。

“所有算法”作为持续扩展的收集目标。按版本公开已收录、待核查、待补充与尚未游戏化的范围，不声称某个有限目录已永久覆盖全部领域。

## 3. 每个知识实体的标准档案

1. 身份：稳定 ID、中文与英文名称、别名、实体类型、领域标签。
2. 问题：为解决什么问题提出，在哪些条件下使用。
3. 内容：直观解释、严谨定义、公式与符号、例子、反例、实现和数值注意点。
4. 关系：必要基础、组成模块、优化对象、相关方法、变体、对比、替代及条件。
5. 资料：一手依据、适合初学者的解释、具体章节或段落、日期和使用范围。
6. 教学：不同理解深度、桥接材料、实验、游戏交互、常见误解与提示。
7. 评价：概念、关键关系、推导或实现、迁移任务和对应量规。
8. 维护：核查人或执行角色、版本、最近核查时间、待解决问题、变更影响。

不是每个实体都必须采用同一种小游戏；任务要体现该知识的机制，而非仅换皮选择题。

## 4. 首批关系示范与玩法方向

以下是待核查的内容与关卡选题，不能直接视为正式评分依据。

| 实体 | 游戏交互候选 | 关系验证方向 |
| --- | --- | --- |
| 损失函数 | 为相同预测选择不同评价目标，观察惩罚如何变化 | 任务目标、误差、损失、参数之间怎样关联 |
| 梯度下降 | 预测一次更新方向，调整步长并观察轨迹 | 损失对参数的梯度怎样参与更新；哪些设置导致困难 |
| L2 正则化 | 调整正则强度，比较参数、目标与训练外表现 | 数据项和惩罚项怎样共同影响优化；与权重衰减的关系需说明优化器与约定 |
| Transformer | 操作词元、掩码与注意力模块，追踪表示变化 | 分词、嵌入、注意力、残差、归一化和训练目标怎样连接 |

优先以“损失—梯度—更新—正则”制作首个算法关系样本，同时把 Transformer 及其他领域纳入全局目录与待建关系。具体先修、公式、机制和答案在来源核查后定稿。

玩家可选择从 Transformer 等目标进入，再由系统定位其所需桥梁。不能要求所有人先机械完成全部基础章节才能看见目标。

## 5. 收录状态与覆盖公开

分别记录内容状态和游戏状态，不能混用：

- 内容状态：候选、已登记来源、已核查、待修订、已归档。
- 游戏状态：未设计、已设计、可试玩、已验证。
- 学习者状态：未知、学习中、支持下完成、独立验证、待复核。

地图可展示已登记但尚无关卡的条目，并明确标识；有条目不等于能学完，有关卡不等于已经验证效果。

覆盖报告按领域列出实体、来源、关键关系、可学习内容与可玩任务的数量及缺口。分母是当前版本的已登记范围，不冒充整个领域的“百分之百”。

## 6. 持续维护工作流

1. 收集新来源或用户缺漏反馈，登记候选实体、别名、时间和出处。
2. 去重与归类，检查是新方法、变体、别名还是更正。
3. 核查原始依据，并选取适合不同基础的讲解；保留分歧与条件。
4. 更新公共图谱及影响分析：关联讲解、公式、代码、任务、答案和个人复验需求。
5. 审核后发布版本与变更记录；旧学习成果继续绑定原版本。
6. 根据误解、检索失败、断点和试学反馈改进内容及玩法。

每次发布检查覆盖缺口和待修订队列；未来的定期巡检频率、维护人员和预算另行确定。目前没有后台采集、监测或定时任务运行。

## 7. 开发顺序修正

全局目录、来源和关系建设从项目早期开始，并持续扩充；游戏化按审核成熟度逐个覆盖。玩法原型可以小，但知识架构、搜索入口和维护机制必须面向广泛覆盖设计。

两项工作交错推进：

- 知识建设：广泛登记、溯源、连接、审校和更新。
- 游戏建设：选取代表性算法关系制作实验与任务，验证后复用模板。

不等待做完整个算法世界才试玩，也不等首个小游戏验证完才开始收集其余算法。
