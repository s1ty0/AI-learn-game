# 个人关系命题与验证目标绑定

日期：2026-11-09。状态：两类关系模板的工程首版；正式掌握、解释自动语义判定和跳级尚未实现。

## 1. 玩家怎样使用

在“我的星图”选择一条连接，写出关系命题、理由和成立条件，主动保存。右侧“这条关系的验证绑定”显示适用的验证模板，玩家明确选择后进入验证室，再确认开始。选择模板只限定本次评价对象，不表示系统已判断原命题正确。

开始前服务器重新检查当前图修订、连线ID、方向、两个知识ID及对应探索。草稿、缺少条件、历史只读视图或过期修订不能直接发起绑定。未覆盖的端点/方向明确提示缺口，不凭名称相似猜测模板。

## 2. 当前两类模板

| 模板 | 方向与实体 | 验证范围 |
| --- | --- | --- |
| lookup-map | token（entity-0144）到词嵌入（entity-0073） | 编号和表行的对应、顺序、同步重排及编号不等于语义距离 |
| mse-example | 损失函数（entity-0138）到均方误差（entity-0014） | 均方误差作为一种具体损失选择、计算约定及评价边界，不宣称所有损失都是MSE |

两类均有结构变化的延后复验，沿用72小时候选规则；未验证观察、帮助标记、同题族或分歧仍不能被复核人数覆盖。普通节点验证与关系验证的题族分开，关系改写后复做同模板仍标为同题族，不能用改一个字刷新独立证据。

## 3. 怎样评价个人命题

验证题引用保存时的关系原文和理由，明确它可能有误，不是标准答案。玩家先解决新情境，再说明原命题哪些成立、哪些需要修正，并给出条件和边界。三个量规仍分别看路径/推导、成立条件和反例边界，同时要求对照个人原命题。

原命题有误时，即便选择答对或解释中已经给出纠正，原关系的路径条目也应记部分满足/缺失；不能把纠正后的句子当作已保存原连线。先保留这次错误证据，再回图修订，旧作答不覆盖。

数值/选择检查只判断给定情境。自由命题是否正确、引用是否充分仍由复核者逐项判断；自动校验不识别所有语义错误。本人复盘、当前意见一致和候选齐备均不自动授予掌握或解锁。

## 4. 具体绑定了什么

作答开始事件保存模板ID、图修订和图内容版本，以及连线ID、source、target、label、note原文副本。关系题目/量规副本和版本也固定保存，后续编辑不会回写本次题目。

当前证据按这五个连线字段核对：

- 修改命题或理由/条件、交换端点、改变方向或删除连线，旧来源状态转为relation_changed；不能直接套用为当前关系证据或继续旧来源复验。
- 移动节点、改节点解释或整理其他位置不改变这条命题，不使其语义绑定失效；开始时的图修订仍可追溯。
- 恢复完全相同的连线ID与原命题/条件后，按当前复核重新判断旧绑定是否一致；保留曾改写和恢复的图历史，不宣称中间状态已被验证。
- 新建另一条同端点连线也不是原ID，不能自动继承旧证据。模板支持范围不等于该条玩家命题已正确。

关系作答不混入节点的星图候选数量；两端节点也不会因这次关系作答自动获得候选。关系面板按作答来源展示原文、缺口、是否匹配当前连线和复验入口，每页30条，可回看更早绑定。

## 5. 数据、并发与恢复

GET `/api/v1/relation-evidence/{edge_id}?offset=0` 只读当前保存连线的模板与绑定记录，端点尚未发现返回404。读接口不改变图、作答或候选。历史图会明确提示下方是当前证据，不允许直接创建绑定。

POST `/api/v1/verification/actions` 新增start_relation，提交edge_id、graph_revision和relation_template。字段不能用于普通start来冒充关系验证，也不能在首次绑定时伪造复验来源。验证室修订与图修订分别检查，图行锁保证引用的保存版本一致；已有未完成情境不被新目标覆盖。

关系复验继续保存同一原命题并检查当前连线一致性。旧来源不匹配时返回待重新核对，而不是清空历史重来。网络故障、409、草稿暂存与精确历史回看沿用原验证室行为。绑定只保存到验证事件，不给个人图增加可信掌握字段，无新表或迁移，仍13张表。
