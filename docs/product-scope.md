# 产品范围与首版目标

日期：2026-11-07。状态：P0 设计草案，未经真实学习者验证。

## 1. 产品要解决的问题

持续收集和维护 AI 与大模型领域的算法及相关知识，把分散资料组织成可探索的游戏地图，减少学习者搜索、筛选和自行拼接知识的时间。帮助初学者找到合适起点，在每轮可克服的挑战中打通知识联系，并保存个人理解与成果。

公共地图需从早期就覆盖损失函数、梯度下降、L2 正则化、Transformer 及其相关算法与机制；游戏关卡按批次完善。详见[算法知识总图](./algorithm-atlas.md)。

核心循环：诊断起点、选择边界任务、探索与实验、解释与建图、独立挑战、保存成果、调整下一轮。

## 2. 用户入口

入口是教学路由，不是固定身份。一个人可以在编程上熟练，在概率上零基础。

| 入口 | 初始可能情况 | 系统如何处理 |
| --- | --- | --- |
| 零基础 | 不熟悉编程和模型术语 | 从生活中的预测任务进入，用操作与解释检查，不先要求代码或矩阵 |
| 有编程基础 | 能写程序，不了解模型评估 | 验证后压缩基础代码操作，重点检查数据和评估概念 |
| 有数学基础 | 能理解公式，但缺少建模经验 | 按需保留公式解释，补充数据、实验和实际限制 |
| 接触过 AI 工具 | 会使用产品，但机制理解未知 | 工具经验单独记录，概念与实践能力另行验证 |

首次用约 10 个诊断任务形成分域画像。目标和兴趣另行收集。年龄、主要用途、设备和单次学习时长尚未确定，不默认特定学生群体。

## 3. 全局收集与首批游戏范围

全局收集以广泛的算法版图为范围；首批游戏样本建议选择“损失函数、梯度下降与 L2 正则化的连接”，同时登记 Transformer 等其他领域的实体、来源与待建关系。首批关卡的规模不限制公共地图收集范围。

这是开发方案，不是已确认的正式课程。内容需经过 P1 来源登记、P2 审校后发布。

算法关系样本的候选成果：

1. 能说明损失函数在选定任务中衡量什么。
2. 能在给定条件下解释梯度与参数更新的关系。
3. 能通过小实验比较不同学习率的影响。
4. 能解释 L2 惩罚怎样进入目标，区分它与数据拟合项，并检查相应适用条件。
5. 能连接目标、梯度、优化与正则，并完成新情境任务。

此前“让预测接受新数据的检验”保留为可复用的基础桥接样本，不再作为全局地图或所有人的固定起点。新样本需要的数学、数据和评估基础按个人缺口接入，不要求先机械学完整套基础课。

## 4. 首版功能边界

包含：全局算法目录与内容状态、来源与关系访问、诊断、任务导航、代表性算法实验、分步讲解、个人局部图谱、解释与挑战、证据记录、历史版本、自适应推荐。

分批实现全部算法的深入教学与玩法。多人社交、复杂经济系统、大型场景、模型微调和全网采集平台暂缓；广泛收集与维护工作从早期开始。

技术基线已选定为浏览器Web：React/TypeScript/Next.js、React Flow、FastAPI和PostgreSQL。首版以桌面交互为工程假设并兼容窄屏阅读；先本地开发，模型供应商和云部署位置尚未绑定。详见[选型决策](./technical-decisions.md)。

## 5. 成果与评价边界

- 内容浏览、关卡完成、独立掌握分别记录。
- 图谱中的事实正确性、关系理解、应用能力分别检查。
- 当次通过不等于永久记住；延后复验提供后续保持情况的证据。
- 单章完成不等于掌握 AI；全局路线与当前版本范围始终可查看。
- 收录目录、内容审核、关卡可玩和玩家掌握分别显示；以持续维护逐步扩大覆盖。
- 每轮挑战匹配是持续调整目标，不能保证每轮都恰好匹配。

## 6. 尚待验证

- 首章场景是否有吸引力，桥接步骤是否足够短。
- 每轮一个核心目标的起始设计是否合适。
- 建图与阅读是否造成额外负担，何时适合由系统辅助排版。
- 不同基础用户的诊断分支、任务跨度和提示层级是否有效。
