# 游戏内个人星图

日期：2026-11-08。状态：单人本地工程原型；探索发现与个人解释均不构成正式掌握认证。

## 1. 玩家怎样使用

1. 点亮知识后，从“更多→我的星图”进入，也可从“我的发现”进入。
2. 默认展开最近已有发现的章节。可切到其他已发现章节或“全部已发现”。首屏和锁区不因此提前暴露全目录。
3. 点击“接入本章发现”，只补缺失节点。旧解释、位置、隐藏节点与连接保留，不自动填写标准答案。
4. 点一颗星写自己的解释。拖接端点连线，或用选择框连接；写明关系含义、理由和条件。错误关系可删除，之后仍可从历史回看。
5. “关系线索”提供两端都已发现的资料关系草稿，显示成立条件。玩家主动采纳后再写自己的理由；草稿未审校，不自动认证为事实或已懂。
6. 点击“保存星图”生成新修订。浏览器草稿暂存只是恢复缓冲，不是数据库保存；成功提示版本号后才确认提交。
7. “历史版本”只读回看，比较节点、解释、关系与位置变化。恢复会复制整张共享图为新版本，包括当前未展示的内容；之后的历史仍保留。

手机支持纵向画布和表单，键盘可用选择框、文本框与按钮完成整理。画布可拖动布局、缩放和选择。

## 2. 与原图谱是什么关系

“我的星图”与“图谱手记”使用同一份 `learner-graph` 和版本历史。星图按真实探索发现筛选显示，未显示的旧图内容仍在完整载荷中；切章不会删节点。完整图谱手记仍支持目录搜索和整理。

本轮不另建图表，不迁移或重置个人记录。个人图仍有150节点、500连接上限；全量公共目录不是必须一次塞进个人图。超过上限需后续扩容或拆分设计。

已有演示节点只有在相应知识已发现时才在星图显示。若它已有个人解释，接入操作不覆盖。新节点引用实际探索的节点ID与内容版本，关系记录线索ID及版本；这些可编辑元数据不是可信评价证据。

## 3. 发现来自哪里

新增只读 `GET /api/v1/discoveries`：

- 根据当前章节配置读取单人演示档案的阶段记录，只有阶段3完成才作为发现。
- 按公共实体ID去重，同一实体保留多个关卡来处、各自内容版本和提示使用情况。
- 只返回已发现章节及实体；关系仅在两个端点都发现时返回，并保留待审状态和来源ID。
- 接口不写个人图、不推进关卡、不更新掌握状态。返回 `mastery=unverified`。

发现名称与关系线索使用当前内容版本；来处保留原探索记录的版本。历史课程正文切换和显式内容迁移尚未实现，不能把当前名称当作历史原文。

## 4. 草稿、故障与冲突

星图与工作台草稿按入口、标签页分开；工作台原草稿键保持兼容。星图编辑后排队写入IndexedDB，避免旧写入在清除之后复活。刷新同一标签页后主动选择找回。浏览器清理存储、存储失败或丢失标签页身份时不能保证恢复。

保存失败保留操作和文字，相同操作重试复用幂等键。两窗口冲突时不自动覆盖：读取最新版本，查看草稿与服务器差异，再选择保留服务器或把完整草稿复制到当前修订。完整复制不是逐字段合并，服务器原版本仍可回看。

只有主动确认的保存进入数据库版本。未提交编辑不会逐笔成为服务端事件；浏览器草稿不等于完整编辑审计。逐编辑留痕、阶段证据绑定、独立掌握评价和自动关系断点判定仍待后续。

## 5. 验证边界

2026-11-09接入只读当前证据：窄范围实体映射、徽标、来源缺口、旧作答精确回看、验证/复验目标和局部补桥。数据通过独立接口与组件上下文呈现，不随图谱保存写入旧快照。历史画布明确区分当前证据；连线只提供两端入口，不由端点候选认证关系。详见[星图证据](./star-evidence.md)。

前端检查隐藏内容保留、重复接入、已有关系不覆盖和差异；真实隔离PostgreSQL检查发现范围、来处去重、只读性、新字段持久化及旧快照保留。浏览器检查接入/写解释/条件、历史恢复、草稿刷新、503重试、双窗口409与390像素布局。

浏览器全部写入独立夹具，不改变真实玩家探索和个人图；后端使用隔离Schema。工程检查不替代事实审校、关系评分或真实学习效果验证。
