# 本地开发与当前实现

更新日期：2026-11-09。定位：单人本地工程原型，教学内容与评价仍待审校，不是完整课程。

默认入口为“迷雾群岛”：按进度只展示当前主要入口。现有九章、28个主线点、9个可选支线，各3步，共111个小机关。规则见[游玩体验](./game-experience.md)、[第一章航图](./information-sea-map.md)与[多章光路](./light-expedition.md)。“更多→我的星图”接通发现与个人理解；完整图谱编辑保留在“更多→图谱手记”（`/workbench`）。

## 1. 在当前电脑启动

所需依赖已经下载。在仓库根目录运行：

```powershell
pnpm dev
```

看到服务就绪后打开 <http://127.0.0.1:3000>。启动脚本顺序执行：启动项目内PostgreSQL、确保learnai数据库存在、应用Alembic迁移、启动FastAPI与Next.js。首次读取内容时创建草稿内容版本与演示图；后续启动保留已有个人记录，不重置图谱。

三个服务仅监听本机：Web 3000、API 8000、PostgreSQL 54329。启动时等待真实探索接口与页面可用后才打印“已就绪”。Web/API日志分别写入 `.runtime/web.log`、`.runtime/api.log`，不依赖终端持续读取子进程输出。

`Ctrl+C`停止本次启动的子进程，并关闭本次启动的数据库；若复用已经运行的同一项目数据库，则不接管它的关闭。不要同时运行两份完整启动脚本；端口占用时先关闭原进程，不删除数据库文件。只需单独启动API时，可运行 `node scripts/dev-app.mjs --api-only`，但必须先确认8000端口未被旧API占用。

启动前现会检查所需Web/API端口，发现已有服务就退出，不启动重复子进程，也不因旧接口返回成功而误报新服务就绪。

Windows使用PostgreSQL官方pg_ctl的受限令牌启动方式，避免直接用管理员身份运行postgres。Codex沙箱中该系统调用可能受限，需要允许 `node scripts/dev-app.mjs` 在沙箱外运行。在自己的普通终端运行不需要Codex沙箱授权。

## 2. 第一次在新环境安装

当前已验证环境：Windows x64、Node.js 24.19.0、Python 3.13.14、pnpm 11.23.0、uv 0.12.5。其他操作系统尚未实测。

先准备Node 24、Python 3.13、pnpm和uv，再执行：

```powershell
pnpm install --frozen-lockfile
uv sync --project apps/api --python 3.13 --frozen --cache-dir .runtime/uv-cache
```

仅运行浏览器自动化检查时，还需下载测试浏览器：

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/.runtime/browsers"
pnpm exec playwright install chromium
```

JS版本固定在根目录pnpm-lock.yaml，Python版本固定在apps/api/uv.lock。PostgreSQL二进制通过开发依赖下载，不依赖Docker、系统服务或新建Windows账号。embedded-postgres包装器版本为18.6.0-beta.19，附带PostgreSQL服务程序为18.6；包装器版本后缀不代表数据库内核为测试版。

## 3. 可体验的完整小循环

默认游玩：进入回声小岛，拨大第三座灯塔信号、打开光闸、组合机关条件并选择解释，完成后点亮“因果掩码”。通过的步骤自动写入PostgreSQL；刷新后可继续，通关后可重游。未过关的滑块位置暂不保存。发现与正式掌握分开。

第一岛完成后开放分光台：将三束偏好调成相同、偏向第三束、转向第一束，通过后介绍Softmax和加权汇聚。前端与后端分别计算权重、输出；后端保存独立阶段记录并拒绝伪造读数。旧岛从我的发现重游。页眉音乐图标可播放《雾海微光》，默认关闭，音量可调，后台自动暂停。音轨为项目自编程序合成，见[音乐说明](./music.md)。

分光台完成后开放寻光镜，学习查询/键产生匹配分数；之后同时开放可选双镜湾与综合归航灯塔。双镜湾比较两个独立查询与输出拼接；归航灯塔组合查询匹配、因果限制、Softmax与汇聚。四个主线点完成即本章主线连通；支线另算全探索状态。仍无熟练度刷题实现。

点击“展开这一程航图”或“更多→这一程的航图”，可查看已揭示的路线、选择可达点与重游；锁区仅显示迷雾。新三岛的二维查询盘可拖动或方向键/WASD操作，坐标滑块仍可用；多头用1/2换镜片，综合机关用空格切光闸、机制卡逐步连接/撤回。初始光灵在交互监听器就绪前显示“正在唤醒”，避免把初始服务端画面当作已可操作状态。

世界操作：方向键/WASD移动光灵，点击地面前往；点击光源自动靠近，或靠近后按E/空格点亮。机关操作：拖动/点击第三座灯塔或使用滑块；方向键调信号，空格开关光闸，Enter继续，最后用1—3选择原因。连接失败也可操作场景，未连接时无法确认通关或伪造存档。

游戏内“我的星图”按已发现章节展开。主动接入缺失节点、写解释、连关系并补条件，保存为新版本；可预览/比较历史、恢复为新修订。与图谱手记共用存档，隐藏旧内容保留，不自动填标准解释。详见[个人星图](./personal-star-map.md)。

图谱手记保留如下整理循环：

1. 在“探索地图”拖动节点、连接端点，点击节点写解释，点击连线修改关系含义。
2. 在“知识图书馆”搜索名称/英文/别名，从160条候选目录加入个人地图。已收录目录不等于已有正文或关卡。
3. 点击“保存地图”“保存解释”或“保存关系”，将当前局部图作为新修订写入PostgreSQL。
4. 在“关卡实验”预测因果掩码的效果，改变第三个值，比较开关掩码后的权重和输出，提交自己的解释。
5. API独立复算数值，保存预测、提示使用、实验条件、解释与评价版本。解释保持待复核，不自动标记掌握。
6. 在“学习足迹”回看作答和地图版本，预览旧图或恢复为新修订。原有历史保留。

地图初始包含7个节点、6条待验证关系。连线、写解释和答对选择题均不构成正式掌握认证。这里的Transformer实验用于工程验证；最终入门路径仍需根据画像选取。

## 4. 草稿、历史与冲突

- **浏览器草稿自动暂存**：工作台修改约250毫秒后、星图编辑后排队写入IndexedDB；按标签页与入口隔离，保留工作台原草稿键。刷新后提示找回。浏览器存储被清理、不可用或标签页身份丢失时，不能保证恢复。
- **服务器明确提交**：目前需主动点击保存。工作台提示“已同步”、星图提示“已保存”及版本号后，才确认数据库快照。草稿暂存不等于服务器自动保存。
- **修订号检查**：两标签页基于同一旧版本保存时，仅一份成功。另一份返回409并保留草稿，需先查看最新版本。
- **显式重新应用**：用户可以保留服务器版本，或把完整草稿复制为新修订。当前没有逐字段自动合并；复制草稿会以草稿内容替换当前图，但原服务器版本仍可回看。
- **重复提交不重复建版本**：同一操作键及相同请求返回已有结果；键相同但内容不同则拒绝。
- **恢复旧图不改旧历史**：复制旧快照为新修订，记录来源版本。星图可比较节点、解释、关系及位置变化；恢复作用于整张共享图，包含当前隐藏内容。当前无逐字段自动合并。

## 5. 内容版本与接口

导入器将实体、关系、6份Transformer专题Markdown、练习源文件、分光台/信息之海配置和正文、扩展章节配置与机制档案组成内容摘要，写入带哈希的草稿版本。正文从数据库中的版本副本读取，不在每次请求时重新读磁盘。重启服务才会导入变更；现有图继续引用原内容版本，不自动迁移。

当前界面正文与搜索读取本次启动的内容版本，尚无旧内容版本切换器。图快照与旧内容记录保留在数据库中；完整的历史课程浏览和显式迁移仍待开发。来源修订、量规、掌握证据及推荐等独立表仍属于设计，不能将当前清单副本等同于完整发布系统。

## 6. 数据在哪里

运行文件全部位于忽略版本控制的 `.runtime/`：PostgreSQL数据目录、随机数据库密码文件、数据库日志、测试浏览器与截图。Python虚拟环境在apps/api/.venv，JS依赖在node_modules。

不要将 `.runtime/db-secret.json`、数据库目录或本地学习记录提交Git。密码由脚本传入子进程环境，不输出到启动日志。该方案是本机开发配置，未接入生产密钥管理。

停止服务后，备份 `.runtime/postgres` 与对应的 `.runtime/db-secret.json` 可保留当前集群文件；正式逻辑导出、跨版本恢复和备份恢复演练尚未实现。不要删除密码文件来重置密码，它与已有集群配对。

自动化浏览器检查使用各测试独立的内存接口夹具，涵盖探索、图谱、历史、作答与多窗口共享修订，不修改真实玩家记录。早期检查产生的开发样本历史保留，不通过清理破坏留痕。后端pytest使用独立临时Schema，检查后只删除自己的测试Schema。
