# 修订后的单缺口挑战

更新日期：2026-11-10。状态：固定情境与留痕工程首版。检查选择是否符合规则；自由解释与修订质量仍需独立复核和真实试学校准。

## 1. 玩家怎样进入

在关系修订任务保存新命题后，展开该次修订足迹，点击“挑战这次修订”。从本次修订选过的条目中，选择推导、条件或边界中的一个目标。每轮只打开一个情境，不要求一次再做三套题。

开始前展示当前已保存命题和条件。服务器重新检查当前连线是否仍与该次修订完全一致，以及图修订、探索前置和已有进行中作答。旧命题被改写、反向或删除后不能直接挑战旧修订；回到修订任务核对。节点移动不改变命题，但旧图修订仍需刷新确认。

已有情境继续保留，不因从修订入口进入而覆盖。未保存草稿、虚构来源和本次未选条目不能作为挑战来源。

## 2. 当前十二种情境

| 关系 | 推导 | 条件 | 边界 |
| --- | --- | --- | --- |
| token→词嵌入查表 | 重复输入、非顺序编号，逐项读取表行 | 交换词表编号时同步交换表行 | 用向量距离反例检查“编号差决定接近程度” |
| 损失函数→均方误差 | 两模型的误差平方平均，比较具体值 | 不同样本数的组均值，按样本数合并 | 本集均值更低不等于逐样本更好或未来必然更好 |
| Softmax→注意力权重 | 指数归一化后汇聚含负V | 相对分数改变需重算权重 | 无dropout/投影的标量范围不等于因果解释 |
| 因果掩码→缩放点积注意力 | 只用允许项计算分母与汇聚 | 全体归一化后清零还需再归一化 | 上游V或旁路仍可能携带未来信息 |

任务是原创固定练习，不是模型动态生成或完整自适应题库。相近情境可能训练相同技能，不宣称十二个独立能力维度。修改命题文字或再次保存修订，不重置同模板同目标的题族曝光。新注意力模板支持按需展开比例/光路小互动，帮助使用由服务端留痕且不能取消，详见[注意力关系与补桥](./attention-relations.md)。

## 3. 提交后反馈什么

1. 先保留判断、解释和帮助标记。未选判断记录未知，不强迫猜测。
2. 再显示本题规则、推导参照和聚焦条目。正确、错误、未知分别记录。
3. 自由解释不按关键词自动判通过。量规要求核对修订命题本身，选择正确而命题仍错误时不能标为满足。
4. 点击“带着反馈继续修订”回到原来源；修订足迹可继续练习或精确回看已提交挑战。

这些挑战用于修订练习，统一为 `kind=revision_challenge`。不进入节点或关系的掌握候选列表，不作为72小时复验来源，不授予掌握或跳级。复核队列仍可逐条查看它们；本人复盘和其他身份的意见追加保存，不能证明正式教学有效性。

## 4. 保存、并发与恢复

复用验证室事件，不新增表或迁移。开始固定题目完整副本、题族、内容版本、当前关系绑定、修订ID、原来源、聚焦条目和修订时图版本。作答后改图不回写旧题、旧解释和旧修订依据。

POST依次锁验证室和图头，检查两份修订，同一事务追加开始记录。不同请求并发最多开启一题；同键原样重试返回原结果。新增可选字段不破坏旧验证请求的幂等摘要。

503保留操作键与输入。409先读最新记录，不覆盖正在进行的题。解释草稿沿用按标签页和作答ID的本机暂存；浏览器清理存储后不保证恢复。所有学习记录仍属于单人 `local-demo`，没有完整多用户隔离。

## 5. 接口和验证

- GET `/api/v1/relation-revisions/challenge/{revision_id}`：只读修订目标、当前图修订和可选条目；不返回答案、参考或量规。
- POST `/api/v1/verification/actions`，`action=start_revision_challenge`：提交 `revision_id`、`revision_focus` 和 `graph_revision`，并沿用验证室修订与操作键。
- GET `/api/v1/relation-revisions/{attempt_id}`：修订足迹增加本次挑战入口与提交摘要；正文仍通过精确作答接口读取。

数据库检查覆盖六种情境、提交前隐藏、原命题固定、未知/错误、候选隔离、版本与来源拒绝、同题族、同键重试和并发。浏览器检查完整往返、精确回看、503重试、409刷新和390像素布局；所有写入用隔离Schema或接口夹具，不消耗真实玩家进度。

已扩展Softmax加权汇聚与因果掩码关系。下一批将挑战结果接回一步领航，给出局部小目标建议，保留未知和原探索；正式掌握、跳级和全图选题继续等待真人独立性、量规及迁移校准。
