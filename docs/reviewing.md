# 复核队列、身份权限与分歧记录

日期：2026-11-09。状态：本机复核工作流首版，尚未完成真实人员独立性确认、量规一致性校准或正式掌握认证。

## 1. 谁能进入

“更多→复核工作台”要求复核者访问钥匙。服务端由钥匙查出固定身份，客户端不能通过提交actor字段伪造人员。未配置、错误或停用的钥匙不能读取队列、详情或提交意见；学习者local-demo身份不能作为复核者。

钥匙是随机生成的访问能力，数据库只保存SHA256摘要。界面用Authorization请求头发送，不放入URL，不写入浏览器存储；退出或刷新后需重新输入。未提交的复核表单仅保留在当前页面，退出或刷新会丢失。身份配置代表维护者授权，不证明钥匙背后确为另一位独立且合格的评价者。

本轮不预置虚构人员，也不替真实玩家生成或提交复核。所有自动测试身份留在隔离Schema或浏览器夹具。

## 2. 本机维护者怎样配置

先运行 `pnpm dev` 应用0006迁移。需要真实复核者时，在另一个终端执行；将示例ID和显示名替换为实际人员：

```powershell
node scripts/reviewer-access.mjs create reviewer_a "真实复核者姓名"
```

ID为3至40位小写字母开头的字母、数字、下划线或短横线，不能是local-demo。创建同名ID或既有凭据文件会拒绝覆盖。钥匙只写入忽略版本控制的 `.runtime/reviewer-keys/reviewer_a.txt`，命令只显示路径，不输出钥匙内容。由维护者在本机打开文件，向对应复核者提供访问能力；当前没有远程交付或账号注册功能。

更换或停用：

```powershell
node scripts/reviewer-access.mjs rotate reviewer_a
node scripts/reviewer-access.mjs revoke reviewer_a
```

rotate生成新钥匙并重新启用该身份，旧钥匙失效。revoke拒绝后续新请求，不删除历史复核，也不自动删除旧文件。数据库更新后如果凭据文件未写成功，可用rotate恢复。目录/文件的符号链接和异常路径会拒绝写入。文件继承本机目录权限；这不是生产密钥管理或完整多用户账号系统。

## 3. 复核怎样提交

队列只包括已提交原文，每页20条；未提交题及其量规不能通过复核接口读取。详情固定引用该次作答开始时的任务/量规版本和星图修订，显示原文、判断与规则检查，不能编辑原文或本人复盘。

每项选择满足、部分满足、缺失或不确定，并说明理由。满足或部分满足必须引用学习者真实原文；任何提供的引用都需确实存在。服务端只能校验引用存在和字段完整，引用是否足够支持结论仍由复核者判断，不能用关键词数量替代语义评价。

工作台在本人的首次复核提交前不展示其他人的逐项意见。提交后才可对照其他意见，避免默认直接照抄。当前学习端仍是单人演示档案，能读取其作答与复核历史，尚无完整学习者账号隔离；因此这不是防绕过的盲评或监考系统，不能仅凭界面隐藏认证独立性。

## 4. 纠正与分歧怎样保留

一个复核者可以追加纠正自己的最新意见，必须引用被替代记录ID并说明改变判断的原因。不能覆盖原意见、代替别人纠正或跳过自己的最新记录。旧记录全部保留，每位复核者只有最新意见进入当前摘要；同一人提交多次不会增加人数。

| 当前记录 | 摘要状态 | 不代表什么 |
| --- | --- | --- |
| 无复核 | pending_review，等待复核 | 未被判不会 |
| 一位复核者 | single_review，待交叉核对 | 一个人勾全满足不等于掌握 |
| 多位逐项判断不同 | disputed，保留分歧条目 | 不按多数票强行消除异议 |
| 意见一致但有部分/缺失/不确定，或预测检查不符/未知 | needs_followup，需要补充或澄清 | 一致并不自动意味着通过 |
| 至少两身份逐项全满足，且选择检查符合 | consistent_review，当前意见一致 | 独立性、迁移和保持仍未认证，不自动解锁 |

全部状态保持mastery=unverified。未确认的人类身份独立性、提示依赖、重复题族、量规校准和复验不能被“意见一致”覆盖。停用访问权限不等于撤销历史意见；正式的撤回、裁决和证据失效规则还需后续设计。

## 5. 接口与数据

新增review_actors和review_cases表，0006迁移后共13张业务表。

- GET `/api/v1/reviewing/me`：检查当前钥匙与身份。
- GET `/api/v1/reviewing?offset=0`：已提交作答队列。
- GET `/api/v1/reviewing/{attempt_id}`：本人复核详情，首次提交前隐藏其他逐项意见。
- POST 同一路径：提交三条量规、原文引用、理由、修订号、操作键及可选的本人纠正链。

写入使用事务锁，首次并发也检查修订。重复同身份、同内容、同操作键返回原修订结果；换身份或变内容复用键拒绝。冲突时界面保留草稿，明确读最新记录后再决定，不自动合并。503保留操作键和表单，原样重试不重复新增。

复核事件不嵌套复制整份历史响应；重试由对应历史前缀重建当时结果，后续复核不会改变旧操作的返回值。每案本地上限1000条，达到时需保留历史再扩容。认证每次请求检查当前钥匙状态，不依赖客户端角色或持久登录标记。

学习者在“把关系讲通”的历史中可刷新查看复核意见和分歧；解释原文仍保持待正式复核，图谱、探索、画像、领航和解锁均不由本接口改写。

## 6. 验证与下一批

隔离数据库检查身份伪造、未授权/停用访问、未提交题隔离、分页、引文/漏项校验、首次并发、幂等历史重建、本人纠正链、分歧/一致/未知及错误预测边界。钥匙CLI在临时目录和测试Schema中验证，不创建真实复核者。

浏览器以独立夹具验证身份进入、逐项意见、追加纠正和旧历史、503/409草稿、手机阅读、停用拒绝与刷新不记钥匙。工程检查不证明已经完成真人独立复核或有效性校准。

候选准入与四类延后复验首版已实现，见[候选证据](./candidate-evidence.md)。复核者可新增独立性观察判断与依据，旧记录保持无法确认。未确认独立性、存在分歧或关键条件缺口时保持待核查，先补证据；正式跳级还需可验证的先修替代路径，不能仅靠复核人数解锁。
