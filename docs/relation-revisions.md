# 从关系缺口到修订任务

日期：2026-11-09。状态：关系修订工程首版；保存修订不等于命题正确、误解消除或正式掌握。

## 1. 怎样进入任务

在“我的星图”选择一条已绑定验证的连接，展开某次来源，点击“把缺口变成修订任务”。先保存星图，未提交草稿和历史只读图不能直接发起修订。当前支持已有四类关系模板，不自动向未覆盖关系编造诊断。

任务只从已提交的关系绑定作答生成，未提交题和普通节点作答不可使用。它对照三个对象：原绑定命题/条件、当前连线、该次作答与复核意见。当前端点或方向已经变化时，返回星图核对，不把旧任务套到另一个关系。

## 2. 玩家具体改什么

1. 选择要澄清的量规条目：路径/推导、成立条件或边界。无意见标为未知，有部分/缺失/不确定意见则提醒澄清，逐项分歧保留。
2. 阅读每位复核者的最新判断、真实引用和理由。意见是定位线索，不是强制替换句子，也不默认多数正确。
3. 自己改写关系命题及理由/条件，说明为什么这样改，并给出反例或不成立的情境。
4. 确认后保存成星图新版本，同时追加修订足迹。只改变这条连接的label和note，其他节点、位置、连接和图历史保留。

没有文字变化时不能假装“已经修订”。空白命题/条件、没有选条目、缺少理由/反例或伪造量规ID会拒绝。自动检查只确认结构与留痕完整，不替代语义评价；写了反例不代表反例有效，仍需后续挑战和复核。

## 3. 足迹保留什么

每次修订记录：来源作答ID、原绑定、修改前后五个关系字段、图版本前后、选定条目、理由、反例、时间、当时复核修订和每位身份的最新意见副本。

之后复核者改变意见，当前任务显示最新意见，旧修订足迹仍显示当时依据。原作答、原命题、旧意见以及本人复盘都不覆盖。当前关系改变后，旧候选仍按原规则标记relation_changed，不用新修订抹去旧问题或自动恢复掌握。

任务可以从当前已编辑过的命题继续修订，始终对照原绑定与当前状态。端点/方向变化或删除连线时停止写入；需要恢复或重新建立新关系，不直接把另一条边当作原关系。

## 4. 保存怎样避免覆盖

POST同时检查验证室修订、来源复核修订和当前图修订。事务依次锁验证室、来源复核和图头，在同一事务内创建GraphSnapshot、GraphOperation并追加relation_revision事件。成功才返回新图版本。

其他窗口修改任一版本时返回409，不自动合并。草稿按标签页和来源作答ID暂存IndexedDB，刷新可找回；先比较当前/草稿命题、条件、理由和反例，再决定是否完整应用。应用草稿不是自动保存或逐字段合并，新提交仍检查最新三份修订。

503保留输入和操作键，原样重试返回原结果，不重复创建图版本。即使之后图又变化，旧操作键仍返回它原先确认的结果。存储被清理、不可用或标签页身份丢失时，不能保证草稿恢复；界面明确提示本机暂存边界。

只有明确提交成功才称“修订已保存到星图vN，尚未验证”。保存已成功但刷新详情失败时，提示刷新，不要求重交。本人修订不写候选通过、不发放经验或解锁，不重置原探索。

## 5. 接口与数据

- GET `/api/v1/relation-revisions/{attempt_id}`：只读任务、当前关系、当时作答、逐项最新意见和修订历史。
- POST 同一路径：操作键、三份修订号、新命题/条件、量规条目、理由和反例。当前学习档案仍为单人local-demo，不是完整多用户权限隔离。

使用现有verification_sessions的relation_revision追加事件和图快照/操作表，无新表或迁移，仍为13表。修订事件不被当成新的作答或独立题族；精确作答读取、复核队列和旧请求重试继续按各自规则运行。

## 6. 验证与下一批

隔离数据库检查只读任务、图版本与足迹的原子保存、无关内容保留、旧图不变、三类冲突、重复请求、真实修订/反例/条目边界、未提交/普通来源拒绝、反向/删除、并发和后来意见不改写历史依据。浏览器用独立夹具检查缺口选择、保存回看、草稿刷新、503重试、409比较再应用及手机阅读，不写真实玩家图谱。

已接通[修订后单缺口挑战](./revision-challenges.md)：修订足迹选择一次只练推导、条件或边界，提交后对照本题规则并返回继续修订。四类关系共十二个固定情境；文字解释仍需独立复核，是否解决缺口仍待校准。练习不进入候选或72小时复验来源，同题重做不当成新独立证据。
