# 新情境作答与可复核量规

日期：2026-11-08。状态：四类原创验证草稿与本人复盘流程已实现；正式独立评价、学习效果校准与跳级未实现。

## 玩家流程

“更多→把关系讲通”主动进入。对应知识探索完成后才显示验证目标；首屏不增加题目列表。每次只进行一个新情境，先作判断，再写关系、成立条件和边界。可以不选择结果，明确记录不知道；解释不确定时可写清卡点，不强迫伪造完整答案。

提交前不展示该次任务的参考解释或量规。提交成功后原文不可覆盖；想改进就另开一次，同题族重做单独标记。本人可对照量规逐条复盘，保存判断、原文引用和理由。每次复盘追加记录，不覆盖以前的复盘或原始作答。

来源是项目原创任务 `apps/api/app/verification_content.py`，没有复制第三方题目。这些情境与领航练习分别管理，但不把同机制换数值自动当作经过独立性校准的新证据。

选择结果仅按题设规则检查，输出符合、不符或未知。自由解释始终待独立复核，不用关键词数量、文章长度或本人勾选授予掌握。即使所有关键词齐全且选择正确，也不会自动通过。复核的示例与易误判边界见[评价样例草案](./verification-review-cases.md)。

## 量规复盘怎样留据

三条分别选择满足、部分满足、缺失或不确定，并说明理由。声称满足或部分满足时，必须引用实际作答中的原文片段；后端只检查引用是否真实存在，不假装判断引用是否足以支持结论。缺失/不确定也需理由，不能通过遗漏量规绕过检查。

这是本人复盘，所有解释保持 `pending_review`、掌握保持 `unverified`。引用一个字、勾选全满足或写“我已掌握”都不构成正式证据。复核者队列、单独访问身份、逐项依据和分歧记录已实现，见[复核工作台](./reviewing.md)。真实人员独立性和量规一致性仍需核实，不能由钥匙身份直接认证。

## 独立性与题目曝光

- 首次未标记帮助，只记录独立性尚未建立；不根据自报直接认证独立完成。
- 学习者标记使用资料、答案、他人或AI帮助时，保存为支持下尝试。
- 同题族重做保留旧记录并标记重复，不重新计算为独立证据；参考关系和量规已展示，不能假装重新闭卷。
- 当前本地工具不保证用户未看外部资料或公开仓库，未实现监考、独立题库权限或完整多用户学习者账号隔离。因此本批不改变解锁，不发放熟练度或正式掌握。

## 数据与恢复

新增 `verification_sessions` 表和0005迁移，独立于探索、画像、领航和个人图。开始时保存完整任务/量规副本、内容版本、题目版本和当时读取的星图修订；后续内容变化不会回写历史题目或改变这次的选择判定。当前图的修改不等于修改已提交证据。

GET `/api/v1/verification` 只读，返回已开放目标、当前未提交题和最近至多10份提交。POST `/api/v1/verification/actions` 支持 start、submit、self_review。原记录全部保留，本地1000条动作上限需后续保留历史扩容。事务锁保护首次创建与并发更新；相同操作重试返回原结果，改内容复用键或旧修订返回冲突。已提交原文不能通过新动作覆盖。

解释草稿按标签页、作答ID暂存IndexedDB。显示本机暂存成功后仍需明确提交；服务器确认后才称为原文已保存。网络失败保留文字和重试键，409需主动重读；题目变更时旧解释单独展示，不误填到新情境。浏览器清理存储、存储不可用、标签页身份丢失时不能保证草稿恢复；本人复盘的未提交表单当前仅在页面内。

## 验证与后续

隔离PostgreSQL检查题目/量规不提前泄漏、四类规则检查、原文与内容版本固定、本人复盘不能认证、引用及量规完整性、未知/帮助/重复题族、首创并发、幂等与冲突，确保原探索/图谱不被改写。浏览器用独立夹具覆盖提交后复盘、历史原文、草稿找回、503重试、409隔离旧题、手机布局和断线返回，不写真实玩家记录。

复核队列与评价者访问权限、逐项证据和分歧已接通；下一批建立候选掌握准入与复验规则；完成一致性校准和迁移覆盖后，再设计正式掌握投影与验证后跳级。当前量规样例仍是开发草稿，不是经过专家独立审核的金标准。
