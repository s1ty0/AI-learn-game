# 多章光路与教学机制

更新：2026-11-08。状态：可玩教学草稿；没有完成独立内容审校或真实试学。

## 1. 交付范围

现有信息之海保留原进度，逐批扩展表征工坊、学习山谷、生成港湾、积木高塔、优化营地和解码航线。总计7章、29个探索点、87个小机关。其中22个主线点、7个可选支线；主线66步，全部支线21步。不是160个候选实体全部游戏化，也不是完整大模型课程。

首页仍只露出当前主要入口。玩家主动打开“群岛总览”后，才查看已经开放的局部路径。未开放海域和节点隐藏名称。已探索的点可从总览或“我的发现”重游。

## 2. 每点为何分三步

1. **先操作。** 只给一个目标，让玩家看到输入改变与结果响应。
2. **换条件。** 更换序列、方向、词表或步长，比较原有关系是否仍成立。步长渡口会故意观察一次发散，真值航标会观察自信选错。
3. **解释联系。** 保留必要条件并选择原因，形成可回看的发现。它是引导下探索记录，不是独立掌握证明。

每步可展开一条线索。错误不扣生命、不清空操作。接口失败保留当前画面，重试使用相同操作键；修订冲突明确要求返回后重新进入。只在服务端验算并成功保存后推进阶段。刷新恢复最近成功保存的一步，不承诺保存每一次滑杆动作。

## 3. 数值、反例和适用边界

详细原创机制档案分别位于[表征](../knowledge/zh-CN/expedition/representation.md)、[学习](../knowledge/zh-CN/expedition/learning.md)、[生成](../knowledge/zh-CN/expedition/generation.md)、[积木高塔](../knowledge/zh-CN/expedition/tower.md)，包含公式、反例、来源和限制。完成探索后可在应用内展开相应档案。

新增[优化营地机制](../knowledge/zh-CN/expedition/optimization.md)和[解码航线机制](../knowledge/zh-CN/expedition/decoding.md)。手选批次不当作无偏随机样本；动量与Adam使用预设梯度回放，不宣称已跑完整训练。Top-p采用包含首次跨阈值候选的最短前缀。抽签关用预设点，不声称真随机；停止灯塔明确提示前缀不计入新增上限，并拒绝终止后的额外推进步数。

- **文本与表示：** 手工玩具词表不是现实模型的tokenizer。Embedding是固定二维表；编号大小不是语义距离。位置信息用标量相加示意，不冒充RoPE。FFN用共享的`max(0,2x-1)`函数，输入可已包含上下文。
- **训练与更新：** MSE三点样本目标为`14/3×(w−2)²`，梯度为`28/3×(w−2)`。学习率0.10与0.30仅分别演示这个目标上的稳定和发散。L2支线采用`(w−1)²+λw²`，不保证任何正则强度都提高测试表现。
- **概率与生成：** 温度只改固定分数导出的分布；低温不保证事实正确。交叉熵示例是自然对数、硬标签、无额外加权的单样本负对数。生成器只依赖末尾符号的固定预测表，尚未运行真实语言模型。
- **缓存：** 固定单层因果注意力例子独立比较最后一行输出；历史两处投影复用后，本步新增投影位置从3减至1，新查询仍读取3处K/V。这是计算结构演示，不是推理速度、显存或真实模型性能基准。
- **模块与反向：** 残差示例的三项是一个位置的特征。LayerNorm按三个特征计算总体式方差，ε=1e−5、γ=1、β=0；零方差仍有限。模块排序采用Pre-LN，不执行真实模型或把它当所有架构的唯一顺序。链式支线用`z=2w,L=(z−3)²`演示单路径，未实现自动微分引擎。

## 4. 存档与版本

- 配置`data/games/expedition.json`及六份正文进入内容摘要和不可覆盖的ContentRelease。总览的章数、点数、机制数和主线总数从配置计算。
- 第一章之外24个探索点分别使用`local-demo:<node>`的AdventureSession；启动时只补缺失记录。沿用现有表，不需要新增迁移。
- 每步追加操作键、请求摘要、阶段、输入、观察值、原因、线索使用、时间和规则版本。服务端重新计算数值，拒绝锁区、伪造读数、跳步、重复键异载荷及过期修订。
- GET `/api/v1/expedition`读取总览；POST `/api/v1/expedition/{node}/moves`推进；GET `/api/v1/expedition/lessons/{chapter}`读取固定白名单档案。
- 已有个人图谱快照、作答和旧岛历史保留。探索发现与正式掌握分开，仍为`mastery=unverified`；不擅自把引导结果写成独立掌握证据。

## 5. 检查与后续

结构检查`python scripts/check_game_chapter.py`验证全部路径无环、实体引用、每点三步、主线不依赖支线。数值与可达条件由Vitest覆盖；真实PostgreSQL测试验证阶段写入、幂等、拒绝伪造、全主线和旧记录保留；浏览器夹具操作第一章外全部72个机关，不消耗真实玩家进度。工作台的提交、历史恢复和多标签冲突也使用每测试共享的内存夹具，真实数据库规则由隔离Schema的API测试负责。
