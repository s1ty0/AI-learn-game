## 2. 每点为何分三步

1. **先操作。** 只给一个目标，让玩家看到输入改变与结果响应。
2. **换条件。** 更换序列、方向、词表或步长，比较原有关系是否仍成立。步长渡口会故意观察一次发散，真值航标会观察自信选错。
3. **解释联系。** 保留必要条件并选择原因，形成可回看的发现。它是引导下探索记录，不是独立掌握证明。

每步可展开一条线索。错误不扣生命、不清空操作。接口失败保留当前画面，重试使用相同操作键；修订冲突明确要求返回后重新进入。只在服务端验算并成功保存后推进阶段。刷新恢复最近成功保存的一步，不承诺保存每一次滑杆动作。

## 3. 数值、反例和适用边界

详细原创机制档案分别位于[表征](../knowledge/zh-CN/expedition/representation.md)、[学习](../knowledge/zh-CN/expedition/learning.md)、[生成](../knowledge/zh-CN/expedition/generation.md)，包含公式、反例、来源和限制。完成探索后可在应用内展开相应档案。

- **文本与表示：** 手工玩具词表不是现实模型的tokenizer。Embedding是固定二维表；编号大小不是语义距离。位置信息用标量相加示意，不冒充RoPE。FFN用共享的`max(0,2x-1)`函数，输入可已包含上下文。
- **训练与更新：** MSE三点样本目标为`14/3×(w−2)²`，梯度为`28/3×(w−2)`。学习率0.10与0.30仅分别演示这个目标上的稳定和发散。L2支线采用`(w−1)²+λw²`，不保证任何正则强度都提高测试表现。
- **概率与生成：** 温度只改固定分数导出的分布；低温不保证事实正确。交叉熵示例是自然对数、硬标签、无额外加权的单样本负对数。生成器只依赖末尾符号的固定预测表，尚未运行真实语言模型。
- **缓存：** 固定单层因果注意力例子独立比较最后一行输出；历史两处投影复用后，本步新增投影位置从3减至1，新查询仍读取3处K/V。这是计算结构演示，不是推理速度、显存或真实模型性能基准。

## 4. 存档与版本

- 配置`data/games/expedition.json`及三份正文进入内容摘要和不可覆盖的ContentRelease。
- 12个新探索点分别使用`local-demo:<node>`的AdventureSession；启动时只补缺失记录。沿用现有表，不需要新增迁移。
