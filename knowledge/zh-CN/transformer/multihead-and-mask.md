# 多头、投影与掩码：把信息访问算清楚

状态：专题草稿。已配教学实现，待独立审校和关卡试玩。

## 1. 先把投影写全

输入X形状为B×T×8，B是批次大小，T是长度。代码用一个8×24的线性映射一次产生Q/K/V，再沿最后维度拆成三个B×T×8张量。

Q是查询，K是键，V是值；它们来自同一输入，但对应不同可学习投影。一次合并计算不等于三者共享同一组参数。

## 2. 两个头的完整维度走查

| 步骤 | 本例形状 | 操作含义 |
| --- | --- | --- |
| 三个投影 | 各B×T×8 | 各自分配表示职责 |
| 分头与转置 | 各B×2×T×4 | 2个头，每头4维 |
| 点积与缩放 | B×2×T×T | 每个查询对每个键的分数，除以√4 |
| 掩码与Softmax | B×2×T×T | 屏蔽不允许位置，再按键维归一化 |
| 汇聚值 | B×2×T×4 | 每个查询得到每头输出 |
| 转置与拼接 | B×T×8 | 恢复位置在前，拼接两个头 |
| 输出投影 | B×T×8 | 重新组合各头特征，准备残差相加 |

Softmax（将分数变成非负且和为1的权重的函数）在本例没有额外随机丢弃，所有行都至少有一个可见键。

## 3. 参数量能复算

本例Q/K/V无偏置，共\(3d^2=192\)个参数，输出投影无偏置，有\(d^2=64\)个，合计256。固定总宽度d时，改变头数并不自动把这些参数翻倍；但每头维度、计算行为和实现约束会改变。

实际库的偏置、共享键值头及其他变体必须另算，不套用本例公式。

## 4. 可见性与损失是两件事

本例的布尔可见矩阵：`True`允许访问，`False`在分数上置负无穷。因果规则为键位置j不大于查询位置i。

填充掩码另行屏蔽无意义的键。代码中的`padding=True`反而表示这是填充，需要取反后接入可见性。变量含义必须与接口一起看。

损失中的`ignore_index`只控制哪些目标参与评价，不负责阻止注意力读取某个输入。填充查询位置仍会计算输出，只是本例应将它们的监督位置忽略；全键被屏蔽直接报错。

## 5. 让实验暴露错误

固定前两个编号，只改后面的编号；前两个位置的输出分数应保持一致。若不一致，先检查因果掩码、归一化维度和是否引入跨位置操作。

再检查每头权重的上三角为0、有效行和为1、被屏蔽键不贡献输出。仅看总损失下降可能漏掉未来泄漏。

## 6. 进阶与边界

多头提供不同投影子空间，不保证每头固定对应一个人类可解释角色。GQA（多组查询共享较少键值头的方法）、MQA（多个查询头共享一组键值头的方法）与本例标准多头不同，后续独立展开。
