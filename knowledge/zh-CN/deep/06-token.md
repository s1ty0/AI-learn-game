# token与tokenizer深入档案

状态：分层教学草稿；含玩具算法示例，未绑定真实模型词表。

token（模型处理文本时使用的切分单位）和tokenizer（把文本转换为这些单位与编号的组件）不是同一个对象。

## 1. 问题与直觉

原始文本必须转换为可计算的表示。切分方式影响序列长度、词表、未见字符串处理及后续计算，但不能仅凭“分得少”认定方案更好。

对同一个词，按整词与按字符处理会得到不同长度；中文、空格、标点和表情的实际行为依赖具体实现。单位可能对应子词、字符、字节片段或特殊符号。

## 2. 定义与符号

需要区分四层：原始字符串；切分后的单位；单位对应的整数编号；编号索引到的嵌入向量。编号为10不代表它的语义是编号5的两倍。

若词表大小为V，嵌入维度为d，查表矩阵可记为\(E\in\mathbb R^{V\times d}\)。长度为n的编号序列\((i_1,\ldots,i_n)\)得到n×d的向量序列\((E_{i_1},\ldots,E_{i_n})\)。V、n、d分别控制不同对象的大小，不能混用。

## 3. 推导与机制

以玩具BPE（通过反复合并符号对构建子词词表的方法）解释“训练切分规则”与“按规则切分”两步：

1. 用带频次的玩具语料构造初始符号序列。
2. 数相邻符号对，按明确定义的策略选择合并。
3. 保存合并顺序、词表与处理约定。
4. 对新字符串应用已学规则，不重新用该字符串训练词表。

例如玩具初始序列为 `[l,o,w,e,r]`，先合并`l+o`，再合并`lo+w`，得到`[low,e,r]`。这仅解释约定下的机械合并，不声称某个真实模型就这样切分`lower`。

## 4. 实现与实验

真实复现至少固定：tokenizer名称、版本或修订、词表、合并/概率模型、文本规范化、预切分、特殊token、截断与填充设置。记录输入的精确字符串；肉眼相同的文本可能有不同编码形式。

编码再解码是否还原原始文本，依赖规范化与特殊符号处理，不能无条件保证逐字节一致。本项目玩具合并只保证其指定例子的行为，尚无真实词表的回归样本。

## 5. 对比与变体

| 方案 | 基本思路 | 需独立展开的问题 |
| --- | --- | --- |
| 整词 | 以完整词为主要单位 | 未登录词、词表规模、语言边界 |
| 字符/字节基础 | 从更细单位构造表示 | 长度、编码边界与后续合并 |
| BPE | 按学习的合并序列构造子词 | 初始符号与训练/应用约定 |
| WordPiece | 使用其词表学习和切分策略 | 不能当作BPE简单换名 |
| Unigram | 使用子词概率模型选择切分 | 训练、最优切分与可选采样 |
| SentencePiece | 一套支持BPE、Unigram等的工具体系 | 不能与单一算法画等号 |

参考[Hugging Face算法说明](https://huggingface.co/docs/transformers/main/tokenizer_summary)。当前表仅建立区别和缺口，完整训练算法仍待独立档案。

## 6. 边界与排错

- 不同模型的token数通常不能仅靠字符数精确换算。
- 文本已被截断时，模型无法利用被移除的信息；检查完整输入流程。
- 特殊token与填充会影响最终长度；长度统计要说明是否包含它们。
- 填充掩码、因果掩码与损失忽略标签是不同机制，需分别设置和验证。

## 7. 图谱与迁移

tokenizer连接数据预处理、词表、嵌入、上下文长度、计算预算和损失有效位置。它不是纯粹的文本美化工具，也不单独决定模型语义能力。

## 8. 任务与评价

入门：区分单位、编号与向量。机制：按给定合并序列处理新字符串。实现：解释怎样固定真实复现实验。迁移：给定超出长度上限的输入，提出检查与处理方案，并说明丢失信息的代价。
