# Transformer深入档案

状态：分层教学草稿；新增一层因果教学模型及模块专题，尚无原始完整架构复现、真实模型试玩或独立教学审校。

Transformer（一类以注意力机制为核心的神经网络架构）需要作为由多个模块组成的系统来理解。

## 1. 问题与直觉

处理序列时，每个位置需要利用其他位置的信息。注意力负责信息汇聚，但表示转换、逐位置计算、位置线索和训练目标也会影响结果。

学习目标分开：能认出模块、能追踪数据流、能计算一个小样本、能实现一个模块、能比较架构变体。看过一张架构图不等于完成全部目标。

## 2. 定义与符号

以单个序列为例，长度为n，隐藏维度为d。token（切分后的文本处理单位）经编号映射为嵌入向量，排成\(X\in\mathbb R^{n\times d}\)。本档案先省略批次维度。

| 对象 | 常见形状 | 说明 |
| --- | --- | --- |
| X | n×d | 进入模块的表示 |
| 单头Q、K | n×d_k | 查询与键，由输入线性投影得到 |
| 单头V | n×d_v | 待汇聚的值 |
| 单头分数与权重 | n×n | 每个查询对每个键的关系 |
| 单头输出 | n×d_v | 加权后的值 |
| 多头拼接 | n×(h·d_v) | h个头的输出拼接 |
| 输出投影 | n×d | 回到残差相加要求的维度 |

\(d_k,d_v\)分别是每头的键和值维度，h是头数。常见实现令\(d_k=d_v=d/h\)，但不应把具体实现约定当作所有注意力结构的定义。

## 3. 推导与机制

下面是教学用的模块数据流：

1. 对X分别线性投影得到Q、K、V；同源输入不等于三者数值相同。
2. 每个头分别计算注意力，拼接后做输出投影。
3. 用残差连接将输入与模块结果相加，要求形状相容。
4. 层归一化处理指定特征维度，位置与顺序依架构约定。
5. 前馈网络对每个位置应用相同层内参数的非线性变换。

在常见两层前馈形式中，\(\operatorname{FFN}(x)=\phi(xW_1+b_1)W_2+b_2\)，\(\phi\)是非线性激活，\(W_1\)为d×m，\(W_2\)为m×d，m为中间维度。它在不同位置共享这两组参数；不代表不同层也共享参数。

原始架构与常见变体可分别读[原论文第3节](https://arxiv.org/html/1706.03762v7)和[D2L中文10.7](https://zh.d2l.ai/chapter_attention-mechanisms/transformer.html)。位置顺序的必要性另见[D2L中文10.6](https://zh.d2l.ai/chapter_attention-mechanisms/self-attention-and-positional-encoding.html)。

## 4. 实现与实验

先实现单头及掩码，再验证多头拼接与投影，最后组合完整层。不要在同一步同时引入未知分词器、整套架构和训练循环。

标准稠密自注意力的分数矩阵有n²个位置对；单头点积成本随\(n^2d_k\)增长，多头和投影还带来其他成本。不能只写“Transformer复杂度为n²”就忽略隐藏维度、前馈层、训练反向或具体内存实现。

训练时整段位置可参与并行计算，不等于自回归生成能一次知道所有未来输出。预填充和逐步解码有不同计算模式，KV缓存等机制需独立讲解。

本项目保留标准库注意力内核，另已新增[一层因果教学模型](../transformer/README.md)，包含多头、前馈、损失、更新和生成。不等同于原始完整编码器—解码器或预训练大模型；未测GPU性能。

## 5. 对比与变体

| 类型 | 信息访问方式 | 需要区别的任务 |
| --- | --- | --- |
| 编码器式 | 常用双向上下文，具体取决于掩码 | 表示与理解任务、相应预训练目标 |
| 因果解码器式 | 当前位置通常不能访问未来位置 | 自回归下一token预测与逐步生成 |
| 编码器—解码器式 | 编码输入，解码时还可访问编码输出 | 条件生成与跨序列注意力 |

这些是架构组织方式，不是按能力排名。现代位置方法、归一化、激活和头的共享等也存在多种设计。不能将原始模块名单作为所有变体的硬性定义。

## 6. 边界与排错

- 形状不符：先追踪每一投影和拼接维度，不用广播凑出能运行的结果。
- 未来泄漏：检查掩码方向、目标错位与数据处理，不只检查模型代码。
- 数值不稳定：检查分数尺度、归一化和精度，保持参考实现可对照。
- 输出貌似合理：不能据此认定内部解释或测试设计正确。
- 注意力权重高：只能先描述该计算中的加权关系，不能单独当作完整因果解释。

## 7. 图谱与迁移

主关系链：文本、tokenizer（将文本切分并转成编号的组件）、token、嵌入、位置信息、注意力、残差与归一化、前馈网络、输出分数、训练损失、优化、生成策略和评价。

这是关系导览，不是固定必修顺序。玩家可从目标追问，系统只补当前理解或实验所必需的桥梁。

## 8. 任务与评价

结构：给出一组形状，指出哪里无法残差相加。机制：解释为什么Q/K/V来自同一序列仍不必相等。迁移：将自注意力换成跨序列注意力，重新确定查询长度与键长度。综合：解释训练并行与生成逐步之间为什么不矛盾。
